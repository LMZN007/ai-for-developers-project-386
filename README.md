## Пользовательский сценарий: от типа встречи до записи

Роли:

- **Владелец** — тот, кто создаёт тип встречи и принимает записи.
- **Гость** — тот, кто записывается на встречу.

Референс: [Cal.com](https://cal.com). Регистрация, подключение внешних календарей и уведомления в сценарий не входят.

### 1. Владелец создаёт тип встречи

1. Открывает раздел **«Типы встреч»** и нажимает **«Создать»**.
2. Заполняет форму:
   - **Название** (например, «Консультация 30 минут»);
   - **Ссылка (slug)** — подставляется из названия автоматически, её можно поменять: `/<владелец>/consultation`;
   - **Описание** — по желанию;
   - **Длительность** в минутах (например, 30).
3. Сохраняет. Новый тип встречи появляется в списке, рядом есть публичная ссылка и кнопка «Скопировать ссылку».

### 2. Владелец задаёт, когда он свободен

1. В разделе **«Доступность»** указывает рабочие часы по дням недели (например, пн–пт, 09:00–18:00) и свой часовой пояс.
2. Из этих часов и длительности встречи получаются свободные слоты. При 30 минутах это 09:00, 09:30, 10:00 и т. д.

### 3. Гость открывает публичную страницу

1. Переходит по ссылке `/<владелец>/consultation`.
2. Видит название, длительность, описание и календарь на месяц. Дни, где есть свободные слоты, можно выбрать.
3. Выбирает день и видит список свободных слотов. Время показано в часовом поясе гостя, пояс можно сменить.

### 4. Гость записывается

1. Выбирает слот.
2. Заполняет форму: **имя**, **email** и, по желанию, **комментарий**.
3. Нажимает **«Подтвердить»**.
4. Видит экран **«Встреча запланирована»**: что за встреча, когда она будет (дата, время, часовой пояс) и кто участвует.

### 5. Запись появляется у владельца

1. Владелец открывает раздел **«Записи» → «Предстоящие»**.
2. В списке видит новую запись: дату и время, тип встречи, имя и email гостя, комментарий.
3. Занятый слот исчезает с публичной страницы, поэтому второй гость не сможет записаться на то же время.

### Итоговая цепочка

```
Создать тип встречи → Задать доступность → Гость открывает ссылку →
Выбирает день и слот → Заполняет форму → Подтверждение →
Запись в «Предстоящих» у владельца (слот занят)
```

## Стек

| Часть         | Инструменты                                                                             |
| ------------- | --------------------------------------------------------------------------------------- |
| Язык          | TypeScript (strict) на Node.js 26                                                       |
| Контракт API  | TypeSpec → OpenAPI 3.1 → SDK (openapi-typescript + openapi-fetch)                       |
| Бекенд        | Fastify + fastify-openapi-glue (маршруты и валидация из OpenAPI)                        |
| Фронтенд      | Vite + React + Mantine                                                                  |
| Тесты         | Vitest                                                                                  |
| Качество кода | Oxlint, oxfmt, jactionlint, проверка типов `tsc`                                        |
| Окружение     | mise (версии, задачи, фоновые процессы), pnpm workspaces, hk (git-хуки), GitHub Actions |

Проект построен по принципу contract-first: API описан в `packages/contract/main.tsp`, а сервер и клиент работают по сгенерированному из него OpenAPI.

```
apps/api/            бекенд (Fastify)
apps/web/            фронтенд (Vite + React)
packages/contract/   контракт TypeSpec и сгенерированный SDK
```

## Установка

Нужны Git и [mise](https://mise.jdx.dev/getting-started.html). Node.js, pnpm и остальные инструменты mise поставит сам нужных версий из `mise.toml`.

```bash
git clone https://github.com/LMZN007/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise trust
mise install
```

`mise install` ставит инструменты, затем автоматически устанавливает зависимости (`pnpm install`), браузер Chromium для браузерного сценария и git-хуки. Если Chromium пропал (например, после очистки кэша), поставьте его снова: `mise run setup`. Переменные окружения настраивать не нужно: порты заданы в `mise.toml` (API — 3000, фронтенд — 5173).

## Использование

Запустить приложение (бекенд и фронтенд работают в фоне):

```bash
mise run dev
```

Откройте http://localhost:5173. Проверить API напрямую: `curl http://localhost:3000/api/health`.

Запустить как в продакшене, без Vite: `mise run start` — собирает фронтенд, и один сервер на порту `PORT` (по умолчанию 3000) отдаёт и API (`/api/*`), и страницы. Так же приложение работает в Docker-образе.

Управление фоновыми серверами:

```bash
mise daemons ls          # состояние
mise daemons logs api    # логи бекенда (или web)
mise daemons stop        # остановить
```

Проверки и разработка:

```bash
mise run check       # все проверки — то же, что запускает CI
mise run test        # тесты
mise run e2e         # браузерный сценарий (Playwright) с настоящим сервером
mise run lint        # линтер и проверка форматирования
mise run format      # автоисправление форматирования
mise run gen         # пересобрать OpenAPI и SDK после изменения контракта
```

Коммиты оформляются по [Conventional Commits](https://www.conventionalcommits.org/ru/) (`feat:`, `fix:`, `docs:` …) — это проверяет git-хук.

## Деплой

**Публичная ссылка:** https://calls-booking-umck.onrender.com — страница записи [/book](https://calls-booking-umck.onrender.com/book), раздел владельца [/admin](https://calls-booking-umck.onrender.com/admin). Если сервис спал, первый запрос откроется примерно через минуту.

Приложение работает в одном Docker-контейнере: один процесс Node отдаёт API (`/api/*`) и страницы, порт берёт из переменной `PORT`. Сервис описан в [`render.yaml`](render.yaml) (Render Blueprint): бесплатный тариф, регион Франкфурт, проверка здоровья по `/api/health`; новый коммит в `main` выкатывается только после зелёного CI.

> **Данные не сохраняются.** Типы встреч и записи хранятся в памяти процесса и пропадают при каждом перезапуске, новом деплое и засыпании сервиса. Бесплатный сервис Render засыпает после 15 минут без запросов; первый запрос будит его примерно за минуту — после этого списки пусты, и владельцу нужно заново создать типы встреч.

Собрать и запустить образ локально (нужен [Docker](https://www.docker.com/products/docker-desktop/)):

```bash
docker build -t calls-booking .
docker run --rm -p 8080:8080 -e PORT=8080 calls-booking   # http://localhost:8080
```

Прогнать браузерный сценарий против любого запущенного сервиса, например опубликованного:

```bash
E2E_BASE_URL=http://localhost:8080 mise run e2e
```

### MCP-сервер Render для Claude Code

Деплоем управляет агент через [MCP-сервер Render](https://render.com/docs/mcp-server). Его конфигурация лежит в репозитории — [`.mcp.json`](.mcp.json) — и не содержит секретов: ключ подставляется из переменной окружения `RENDER_API_KEY`.

1. Создайте API-ключ: Render → [Account Settings → API Keys](https://dashboard.render.com/u/settings?add-api-key).
2. Сохраните его в переменной окружения **вне репозитория**, например добавьте в `~/.zshrc` строку `export RENDER_API_KEY="<ваш ключ>"` и перезапустите терминал и VS Code.
3. Откройте проект в Claude Code и разрешите проектный MCP-сервер `render`, когда он спросит (или через `/mcp`). В `/mcp` сервер должен быть в статусе connected.
4. Попросите агента выбрать рабочее пространство: «Set my Render workspace to <имя>».

Не вписывайте ключ в `.mcp.json` и другие файлы репозитория. Если ключ всё же попал в коммит — сразу отзовите его в Render и создайте новый.
